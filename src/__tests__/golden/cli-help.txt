=== agent-chat
Usage: agent-chat [options] [command]

cross-session messaging for Claude Code

Options:
  -V, --version              output the version number
  -h, --help                 display help for command

Human commands:
  inbox [options]            what your agents need from you
  answer <id> <text...>      answer a question; routes back to the asker
  dismiss <id>               close an item without answering, or decline an endorsement
  approve <id> <allow|deny>  answer an agent's permission prompt from here
  endorse [options] <id>     approve a composed message; delivers it with your authority
  digest [options]           morning digest: asks, decisions, done, stalled, spend and next picks

Commands:
  service                    run and inspect the broker daemon
  mirror                     project the human queue into a Matrix room and fold phone verdicts back
  burndown                   pick and run unattended work for opted-in initiatives
  seats                      autonomy seats: the idle watchdog
  debug                      diagnostics: sessions, history, routing
  doctor                     check the things that fail silently
  lifecycle                  offline maintenance of the agent lifecycle ledger
  help [command]             display help for command

Agent commands:
  watch [options] <name>     stream messages for a session that cannot receive channel pushes
  agent                      durable agents
  teleport                   teleport control
  handoff                    stored teleport handoffs
  profiles                   agent profiles available to spawn with
  gh-write <gh-args...>      one gh write after --, spaced machine-wide and retried on the secondary
                             rate limit
  suite-slot <command...>    run a full test suite after --, holding one of the machine-wide
                             full-suite slots
  leak-scan [options]        scan added lines for private data; exit 0 clean, 1 findings, 2 cannot
                             pass
  pr-ready [options]         before gh pr create: clean tree, rebase, checks, changeset, leak scan;
                             exit 0 only when all pass

=== agent-chat service

run and inspect the broker daemon

  -h, --help         display help for command

Commands:

=== agent-chat seats
Usage: agent-chat seats [options] [command]

autonomy seats: the idle watchdog

Options:
  -h, --help                    display help for command

Commands:
  watchdog [options]            wake an autonomy seat idle with budget and eligible work (CC-203),
                                and resume a seat that went dark with no teleport (CC-320); silent
                                otherwise. Never wakes or resumes a seat named in the `stopped` map
                                of $AGENT_CHAT_HOME/seat-watchdog.json ({"stopped": {"<seat>":
                                "<reason>"}}; delete the entry to re-enable), a seat at its spend
                                stop, or any seat while the owner seat has announced a broker
                                restart without "restart done". A latest journal line starting WRAP,
                                PARKED or BUDGET-PAUSE stops both the wake and the resume until the
                                seat logs an ordinary line. An unparsable seat-watchdog.json is an
                                error and the run does nothing
  status [options] <seat>       what a seat reads before it dispatches (CC-317), read-only:
                                implementers, reviewers and planners against their caps, its other
                                running agents, parked implementers, the pool reading with its age
                                and the charter stop that applies, the pace of every pool against
                                its glide path, unread inbox messages since the seat last sent one,
                                the machine-wide headless agents, free memory and full-suite slots
                                against their limits, swap used, and the top eligible tasks. A spend
                                cap with no saved meter to count it is a stop
  tick [options] <seat>         one seat's burndown decision on demand (CC-889): the dispatches the
                                tick would make for it under its service-check stop line, trust
                                gate, role and worktree caps and pool gate, and why every other task
                                was refused. Dry run only: it spawns nothing and writes no ledger
  dispatches [options] <seat>   one folded record per agent run from a seat's dispatch log (CC-332),
                                read-only: the broker's spawn and retire rows and the seat's own
                                rows merged, with the spend. Lines that are not a JSON object with
                                an agent and seat outcomes outside the end states are counted, not
                                fatal
  boot [options] <seat>         one boot digest for a coordinator seat (CC-318), read-only: the seat
                                file's frontmatter, the queue's In flight and Next sections, the
                                newest State at teleport section of today's log, inbox messages
                                after a cutoff and the seat status, in 6,000 characters. Over that
                                the oldest inbox lines go first, then the log section; the queue and
                                status are never cut
  run-start [options] <seat>    start a new run for a seat when the owner messages it (CC-472): sets
                                the seat's run meter in $AGENT_CHAT_HOME/seat-watchdog.json to
                                {since: now, last: <pool seven_day now>, spent: 0, before: <old
                                last>} under the watchdog run lock, leaving every other entry as it
                                was. Refuses and writes nothing on unknown_seat, no_reading (no
                                seven_day reading, or one over 15 min old) or lock_held (a watchdog
                                run held the lock for 90 s)
  watchdog-install [options]    install the launchd job (systemd --user units on Linux) that runs
                                `seats watchdog` four times an hour; the first run waits for the
                                next scheduled minute
  watchdog-uninstall [options]  stop the watchdog job and keep it from starting at login; on Linux,
                                also remove its units
  watchdog-status [options]     launchd state of the watchdog job, or its systemd units on Linux
  help [command]                display help for command

=== agent-chat seats watchdog
Usage: agent-chat seats watchdog [options]

wake an autonomy seat idle with budget and eligible work (CC-203), and resume a seat that went dark
with no teleport (CC-320); silent otherwise. Never wakes or resumes a seat named in the `stopped`
map of $AGENT_CHAT_HOME/seat-watchdog.json ({"stopped": {"<seat>": "<reason>"}}; delete the entry to
re-enable), a seat at its spend stop, or any seat while the owner seat has announced a broker
restart without "restart done". A latest journal line starting WRAP, PARKED or BUDGET-PAUSE stops
both the wake and the resume until the seat logs an ordinary line. An unparsable seat-watchdog.json
is an error and the run does nothing

Options:
  --dry-run           print each seat decision; wake nothing, write nothing
  --replay <value>    run a past UTC day (YYYY-MM-DD) from events.db, read-only
  --seat <value>      only this seat (repeatable); default every seat in the charter
  --reading <value>   replay budget reading <ISO>=<five_hour>/<seven_day> (repeatable)
  --root <value>      autonomy directory holding charter.md, seats/ and logs/
  --fire-cap <value>  wakes with no implementer before holding until the seat shows activity
                      (default 2)
  -h, --help          display help for command
