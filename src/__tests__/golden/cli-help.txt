=== agent-chat
Usage: agent-chat [options] [command]

cross-session messaging for Claude Code

Options:
  -V, --version              output the version number
  -h, --help                 display help for command

Human commands:
  inbox [options]            what your agents need from you
  queue [options]            read the human queue; read-only, it cannot answer, approve or endorse
  answer <id> <text...>      answer a question; routes back to the asker
  dismiss <id>               close an item without answering, or decline an endorsement
  approve <id> <allow|deny>  answer an agent's permission prompt from here
  endorse [options] <id>     approve a composed message; delivers it with your authority
  digest [options]           morning digest: asks, decisions, done, stalled, spend and next picks

Commands:
  service                    run and inspect the broker daemon
  mirror                     project the human queue into a Matrix room and fold phone verdicts back
  burndown                   pick and run unattended work for opted-in initiatives
  seats                      autonomy seats: the idle watchdog
  port                       JSON envelope ports for the dispatch factory; none of them starts a
                             broker
  machine                    operator HOLDs, owner stops and the machine stop
  host                       host launchers: machines a teleport can land a successor on
  debug                      diagnostics: sessions, history, routing
  doctor                     check the things that fail silently
  lifecycle                  offline maintenance of the agent lifecycle ledger
  help [command]             display help for command

Agent commands:
  watch [options] <name>     stream messages for a session that cannot receive channel pushes
  agent                      durable agents
  teleport                   teleport control
  handoff                    stored teleport handoffs
  profiles [name]            agent profiles available to spawn with
  gh-calls [options]         read the GitHub call log: top callers and routes, and 403s split by
                             limit
  counts [options]           every count derived from live state, beside what each surface shows,
                             with a verdict per difference
  operator-brief [options]   one read-only status block per coordinator seat: live and finished
                             agents, Shepherd PRs and gates, unread count, plus pools, the machine
                             stop, burndown and the owner queue. Never runs gh
  gh-write <gh-args...>      one gh write after --, spaced machine-wide and retried on the secondary
                             rate limit
  suite-slot <command...>    run a full test suite after --, holding one of the machine-wide
                             full-suite slots
  leak-scan [options]        scan added lines for private data; exit 0 clean, 1 findings, 2 cannot
                             pass
  pr-ready [options]         before gh pr create: clean tree, merge the base, checks, changeset,
                             leak scan; exit 0 only when all pass
  codex                      run Codex sessions on the agent-chat bus

Service commands:
  ask [options] [text...]    put a question to the human under a service label and print its msg_id
  answers [options] <name>   read answers and dismissals to a service label's asks

Commands:
  plan [options]                dry run: what the tick would dispatch now, and why every other task

                                refusal mix, registrations, tick health

                                the ceilings
  pause [options]               stop new spawns from the next tick on; running agents finish
  resume [options]              let the tick spawn again
  release [options] <task>      drop every claim on a task, stalled or not, so the tick may pick it
                                again; --slice drops only that slice
  link [options] <task>         record a hand-dispatched PR on a queued, released or unlinked
                                implementing slice, so the tick finishes it on merge
  unstall [options] <task>      reload an outside-owns slice's owns from its plan and clear the
                                stall in place, keeping its PR and agents
  reload-owns [options] <task>  reload a live slice's owns from its plan when its branch fits them,
                                keeping its phase, PR and agents
  done [options] <task>         finish a PR-less implementing or queued slice by hand, so its
                                dependents dispatch; retires its agents
  landed [options]              every open, unreconciled task in a seat's scope that a recent
                                default-branch subject or Covers clause names (CC-611); writes
                                nothing
  classify [options]            classify every open task on, off or ambiguous against section 2 of
                                the accepted plan; --write publishes off-plan-<date>.md (TP-2418)
  config                        resolved burndown settings (CC-955)
  preset                        named burndown settings presets (CC-955)
  override                      a time-boxed patch over the settings (CC-955)
  seat                          turn a seat on or off in the settings (CC-955)
  install [options]             print the sign-off checklist, then install and start the launchd
                                tick job (a systemd --user timer on Linux)
  uninstall                     stop the launchd tick job and keep it from starting at login; on
                                Linux, also remove its units
  job-status                    launchd state for the tick job (its systemd units on Linux): loaded,
                                pid, and whether it may spawn
  help [command]                display help for command

=== agent-chat seats
Usage: agent-chat seats [options] [command]

autonomy seats: the idle watchdog

Options:
  -h, --help                      display help for command

Commands:
  watchdog [options]              wake an autonomy seat idle with budget and eligible work (CC-203),
                                  and resume a seat that went dark with no teleport (CC-320); silent
                                  otherwise. Never wakes or resumes a seat named in the `stopped`
                                  map of $AGENT_CHAT_HOME/seat-watchdog.json ({"stopped": {"<seat>":
                                  "<reason>"}}; delete the entry to re-enable), a seat at its spend
                                  stop, or any seat while the owner seat has announced a broker
                                  restart without "restart done". A latest journal line starting
                                  WRAP, PARKED or BUDGET-PAUSE stops both the wake and the resume
                                  until the seat logs an ordinary line. Pages tp-operator once per
                                  live seat blocked on AskUserQuestion over 5 min (CC-1057). An
                                  unparsable seat-watchdog.json is an error and the run does nothing
  status [options] <seat>         what a seat reads before it dispatches (CC-317), read-only:
                                  implementers, reviewers and planners against their caps, its other
                                  running agents, parked implementers, the pool reading with its age
                                  and the charter stop that applies, the pace of every pool against
                                  its glide path, unread inbox messages since the seat last sent
                                  one, the machine-wide headless agents, free memory and full-suite
                                  slots against their limits, swap used, and the top eligible tasks.
                                  A spend cap with no saved meter to count it is a stop
  tick [options] <seat>           one seat's burndown decision on demand (CC-889): the dispatches
                                  the tick would make for it under its service-check stop line,
                                  trust gate, role and worktree caps and pool gate, and why every
                                  other task was refused. Dry run only: it spawns nothing and writes
                                  no ledger
  dispatches [options] <seat>     one folded record per agent run from a seat's dispatch log
                                  (CC-332), read-only: the broker's spawn and retire rows and the
                                  seat's own rows merged, with the spend. Lines that are not a JSON
                                  object with an agent and seat outcomes outside the end states are
                                  counted, not fatal
  log [options] <seat> <text...>  append one line to a seat's journal (CC-1058): '<HH:MM> <text>' in
                                  <root>/logs/<seat>/<YYYY-MM-DD>.md, stamped from the machine clock
                                  in local time, and print the file. Refuses and writes nothing on
                                  an unknown seat, a line break in the text, or text that opens with
                                  a time ('10:00 standup moved' becomes 'standup moved to 10:00')
  boot [options] <seat>           one boot digest for a coordinator seat (CC-318), read-only: the
                                  seat file's frontmatter, the In flight derived from burndown
                                  claims, Shepherd rows, the roster and verdicts, the top in-scope,
                                  fresh brief:ready tasks in the gate's ready order with their age,
                                  the queue's Next section, the newest State at teleport section of
                                  today's log, inbox messages after a cutoff and the seat status, in
                                  6,000 characters. Over that the oldest inbox lines go first, then
                                  the log section, then the queue, In flight, Next, seat and status
                                  sections
  run-start [options] <seat>      start a new run for a seat when the owner messages it (CC-472):
                                  sets the seat's run meter in $AGENT_CHAT_HOME/seat-watchdog.json
                                  to {since: now, last: <pool seven_day now>, spent: 0, before: <old
                                  last>} under the watchdog run lock, leaving every other entry as
                                  it was. Refuses and writes nothing on unknown_seat, no_reading (no
                                  seven_day reading, or one over 15 min old) or lock_held (a
                                  watchdog run held the lock for 90 s)
  watchdog-install [options]      install the launchd job (systemd --user units on Linux) that runs
                                  `seats watchdog` four times an hour; the first run waits for the
                                  next scheduled minute
  watchdog-uninstall [options]    stop the watchdog job and keep it from starting at login; on
                                  Linux, also remove its units
  watchdog-status [options]       launchd state of the watchdog job, or its systemd units on Linux
  heartbeat-install [options]     render one systemd --user service and timer per seat (CC-947) that
                                  fires on the seat file's heartbeat_cron minutes and sends the
